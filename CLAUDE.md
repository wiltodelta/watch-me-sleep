# Watch Me While I Fall Asleep

You are a **principal Swift/macOS engineer** maintaining a menu bar app that puts the Mac to sleep once its user falls asleep: one automatic night watch (`SleepSupervisor`) plus a manual timer (`TimerManager`) that every sleep goes through. SwiftPM; the one dependency is Sparkle (in-place updates, `Updater`; packaging and keys in `docs/build-and-release.md`).

Shared rules for our macOS apps: `~/Documents/GitHub/claude-config/docs/macos-apps.md`; this file states only what differs.

## How to run

- `./create-app.sh` - build and assemble the standalone .app bundle (version from the latest tag, icon compiled from `App Icon.icon` (its layers drawn by `scripts/draw-icon.py`; icon.json edited in Icon Composer) plus `MenuIcons.xcassets` by actool, Sparkle embedded) and sign it with the team's Developer ID (hardened runtime plus the camera entitlement; the hardened runtime blocks the camera without it). The TCC grant the stable signature preserves is Camera. A local release build is `RELEASE=1 ./create-app.sh && ./notarize.sh` (`docs/build-and-release.md`).
- `./capture-screenshots.sh` - rebuild and regenerate light/dark `screenshots/` through Accessibility identifiers and ScreenCaptureKit, with the camera off; needs Accessibility and Screen Recording for the terminal and an unlocked session. Restores the development defaults and quits its own timer/app on exit. Leave the Mac alone while it runs; recipe: `docs/screenshots.md`.

## Test and lint

- `bash maintain.sh` - the canonical Swift gate.
- `swiftlint` must be installed for the lint step (`brew install swiftlint`); `maintain.sh` fails without it. It lints `Sources` and `Tests`. It fails the gate on a file over 500 lines or a function over cyclomatic complexity 10: split by type or extract a helper.
- The right-click menu opens only on a real right click; checks reach it through the status button's `Show Menu` accessibility custom action. Pass the complete name returned by `AXUIElementCopyActionNames`, including metadata, as `docs/macos-capture.md` in claude-config describes.
- The dev build (`com.wiltodelta.watchmesleep.dev`) keeps its journal in `~/Library/Logs/WatchMeSleep Dev` and has its own camera grant. Both night watches can act at once: quit one before testing sleep.
- Running the bare `.build/debug/WatchMeSleep` shows Sparkle's modal "Unable to Check For Updates", and its modal loop stalls the timer's ticks; it and `xctest` also hold no Camera grant, so the night watch's camera look answers `unavailable` there. Exercise the camera path from the signed bundle.
- To debug a real night, read the opt-in diagnostics journal (`Journal`, JSON Lines in `~/Library/Logs/WatchMeSleep/`, on with the `Diagnostics.journal` default; events and `jq` recipes: `docs/diagnostics.md`). Record a new decision there when adding one. Watch a night live with `/usr/bin/log stream --level info --predicate 'subsystem == "com.wiltodelta.watchmesleep"'`; `.info` is not persisted (global Swift rule).
- While the Mac is in use (`capture-screenshots.sh` needs it idle), render a changed view from a throwaway `@testable` test with `ImageRenderer` in both color schemes; it shows layout and text, not the Liquid Glass backing, and draws AppKit-backed controls (a `.switch` toggle) as a yellow placeholder.
- Stale `.build` after the repo moves paths fails with a `SwiftShims ... module cache path` error - fix with `rm -rf .build`.
- The seams the global testing rules require are `TimerManager.sleepHandler` (unoverridden, it runs the real `pmset sleepnow`), the `now: () -> Date` clock plus `tick()` (worked example: `TimerManagerTests.testVeryShortTimer`), `TimerManager.idleSecondsProvider`, `TimerManager.volume` and `TimerManager.workHolders` (unoverridden, the real HID idle time, the real output volume of the final minute, and the real power assertions), `SleepSupervisor`'s `idleSecondsProvider`, `wakeHolders`, `cameraAuthorized`, `checkPresence` and `timer` (unoverridden, `checkPresence` turns the real camera on), and `UserDefaults(suiteName:)`. Reset `now` in `setUp`/`tearDown`, because the manager is a shared singleton and the override outlives the test that set it.
- Tests of `putComputerToSleep` itself must replace `TimerManager.powerCommand` and `showPowerFailure`: `sleepHandler` bypasses this path. `PowerCommandTests` exercises harmless executables; no test runs real `pmset`.

## Night watch

- `NightWatchPolicy` (pure) decides from input idle time, `WakeHolders` and the camera; `SleepSupervisor` runs it every 10 s in bedtime and owns one action per idle stretch. Its thresholds are constants, not settings, on purpose. The camera answers only "something plays, nobody touches the Mac"; a quiet Mac never turns it on. Bedtime is minutes after midnight (`bedtimeStart`/`bedtimeEnd`), carried over once from the old whole-hour keys. `watchNow()` runs it outside bedtime for a nap (`isWatchingNow`, not persisted) until `willSleep`, `screensDidSleep` or the start of bedtime.
- Absence is evidence only after a face in the same stretch (`Stretch.faceSeen`); before that it counts as unclear, and mostly black frames (`PresenceCheck.darkLuma`, unmeasured against real nights) are unclear too. `WakeHolders.soundOnly` (media without any display hold) plus `keepsSoundPlaying` makes the night watch stand aside; the choice is asked once at launch (`soundChoiceAsked`).
- A timer the night watch starts (`TimerManager.stopsOnInput`) stops at any input since its start, and on open eyes in its final minute, after which the stretch resumes looking; a timer set by hand is an intent and postpones by `postponeMinutes` instead. Only camera-armed timers look in the final minute: a quiet Mac's and the three-hour "still watching?" never do. A test that advances `clock` past a night watch timer's start must advance `idle` with it, or the timer reads the stale idle as input.
- `WakeHolders` sorts power assertions by measured properties, never app names: a display-only assertion or a process in CoreAudio's playing list is media; a process's own system assertion is work, which turns the final action into `pmset displaysleepnow`. Apps (`.app/`) are never daemons, Apple's under `/System/Applications` included. Re-measure with `IOPMCopyAssertionsByProcess` before changing a rule.
- `CameraWatcher` runs the session while any user (the night watch's look, the Settings preview) holds it, and never prompts for access. Canceling a look releases only `.look`; queued answers are generation-checked before release or delivery. `CameraWatcherTests` injects authorization and session control, and `SleepSupervisorTestCase` replaces both `checkPresence` and `cancelPresence`. Verify the camera went off from the log (`category == "camera"`: "Camera on for …", "Camera off"); drive the Settings preview through its `toggleCameraPreview` Accessibility identifier. The README capture recipe keeps the camera off (`docs/screenshots.md`).
- A timeout without the full `PresenceCheck.lookSeconds` of frame observation is `unavailable`, even with frames. `SystemVolumeFader` follows output changes with separate original volumes; `VolumeFaderTests` injects every device operation. `LaunchAtLoginManagerTests` uses a fake `LoginItemService` and an isolated notification center, never real login-item registration.
- `PresenceCheck` measures seconds from frame timestamps, never frame counts: the built-in camera delivered ~14 fps where 10 were asked (measured 2026-10-05), and auto exposure can slow it in the dark. `EyeReading` combines Vision's EAR (below 0.20) and Core Image's blink classifier: both must agree when both return a result; a lone result decides otherwise. EAR alone took 17 of 46 open-eyed photos for closed. Change either rule only against `EyeDetectionBenchmark` (skipped without `WMS_FACE_DIR`; method, results and caveats in `docs/eye-detection.md`). To watch a look live, log from inside `WatchMeSleepCore` (the executable target cannot see internal API) and launch the signed bundle with `open --env`, so TCC asks about the app, not the terminal.
