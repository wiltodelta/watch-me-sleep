# Watch Me While I Fall Asleep

You are a **principal Swift/macOS engineer** maintaining a menu bar app that puts the Mac to sleep once its user falls asleep: one automatic night watch (`SleepSupervisor`) plus a manual timer (`TimerManager`) that every sleep goes through. SwiftPM; the one dependency is Sparkle (in-place updates, `Updater`; packaging and keys in README "Building and releasing").

## How to run

- `./create-app.sh` - build and assemble the standalone .app bundle (version from the latest tag, icon compiled from `App Icon.icon` plus `MenuIcons.xcassets` by actool, Sparkle embedded) and sign it with the team's Developer ID (hardened runtime plus the camera entitlement; the hardened runtime blocks the camera without it). The TCC grant the stable signature preserves is Camera. Releases: `RELEASE=1 ./create-app.sh && ./notarize.sh` locally, or a `vX.Y.Z` tag, which CI signs and notarizes from repository secrets (`docs/build-and-release.md`).
- `./capture-screenshots.sh` - rebuild and regenerate `screenshots/` through Accessibility identifiers; needs Accessibility and Screen Recording for the terminal, turns the camera on briefly for the Settings preview (needs **Use the camera** on and access granted to the build) and blurs it; refuses a capture another window covers, so leave the Mac alone while it runs. Quit an installed copy first, or the single-instance check quits the fresh build.
- `Package.swift` stamps a macOS 26 SDK version into the executable through `linkerSettings`; without it Xcode 27's Swift Build records the deployment target there and macOS runs the pre-Tahoe compatibility look. Check a binary with `vtool -show-build`: `docs/ui-architecture.md`.

## Test and lint

- `bash maintain.sh` - the canonical Swift gate.
- `swiftlint` must be installed for the lint step (`brew install swiftlint`); `maintain.sh` skips linting if it is missing. It fails the gate on a file over 500 lines or a function over cyclomatic complexity 10: split by type or extract a helper.
- The app quits on launch if another instance with its bundle id runs; test a second copy beside the installed one under a different `CFBundleIdentifier` (and remove its TCC rows afterwards).
- "Launch at login" registers whichever bundle is running, so toggling it in a dev build points the login item at the repo copy; check with `sfltool dumpbtm`.
- Running the bare `.build/debug/WatchMeSleep` shows Sparkle's modal "Unable to Check For Updates", and its modal loop stalls the timer's ticks; it and `xctest` also hold no Camera grant, so the night watch's camera look answers `unavailable` there. Exercise the camera path from the signed bundle.
- To debug a real night, read the opt-in diagnostics journal (`Journal`, JSON Lines in `~/Library/Logs/WatchMeSleep/`, on with the `Diagnostics.journal` default; events and `jq` recipes: `docs/diagnostics.md`). Record a new decision there when adding one. The app logs at `.info`, which the unified log does not persist: `log show` after the fact returns nothing, so watch a night live with `/usr/bin/log stream --info --predicate 'subsystem == "com.wiltodelta.watchmesleep"'` (zsh's `log` builtin shadows the bare name).
- While the Mac is in use (`capture-screenshots.sh` needs it idle), render a changed view from a throwaway `@testable` test with `ImageRenderer` in both color schemes; it shows layout and text, not the Liquid Glass backing, and draws AppKit-backed controls (a `.switch` toggle) as a yellow placeholder.
- Stale `.build` after the repo moves paths fails with a `SwiftShims ... module cache path` error - fix with `rm -rf .build`.
- The seams the global testing rules require are `TimerManager.sleepHandler` (unoverridden, it runs the real `pmset sleepnow`), the `now: () -> Date` clock plus `tick()` (worked example: `TimerManagerTests.testVeryShortTimer`), `TimerManager.idleSecondsProvider`, `TimerManager.volume` and `TimerManager.workHolders` (unoverridden, the real HID idle time, the real output volume of the final minute, and the real power assertions), `SleepSupervisor`'s `idleSecondsProvider`, `wakeHolders`, `cameraAuthorized`, `checkPresence` and `timer` (unoverridden, `checkPresence` turns the real camera on), and `UserDefaults(suiteName:)`. Reset `now` in `setUp`/`tearDown`, because the manager is a shared singleton and the override outlives the test that set it.

## Night watch

- `NightWatchPolicy` (pure) decides from input idle time, `WakeHolders` and the camera; `SleepSupervisor` runs it every 10 s in bedtime and owns one action per idle stretch. Its thresholds are constants, not settings, on purpose. The camera answers only "something plays, nobody touches the Mac"; a quiet Mac never turns it on. Bedtime is minutes after midnight (`bedtimeStart`/`bedtimeEnd`), carried over once from the old whole-hour keys. `watchNow()` runs it outside bedtime for a nap (`isWatchingNow`, not persisted) until `willSleep`, `screensDidSleep` or the start of bedtime.
- Absence is evidence only after a face in the same stretch (`Stretch.faceSeen`); before that it counts as unclear, and mostly black frames (`PresenceCheck.darkLuma`, unmeasured against real nights) are unclear too. `WakeHolders.soundOnly` (media without any display hold) plus `keepsSoundPlaying` makes the night watch stand aside; the choice is asked once at launch (`soundChoiceAsked`).
- A timer the night watch starts (`TimerManager.stopsOnInput`) stops at any input since its start, and on open eyes in its final minute, after which the stretch resumes looking; a timer set by hand is an intent and postpones by `postponeMinutes` instead. Only camera-armed timers look in the final minute: a quiet Mac's and the three-hour "still watching?" never do. A test that advances `clock` past a night watch timer's start must advance `idle` with it, or the timer reads the stale idle as input.
- `WakeHolders` sorts power assertions by measured properties, never app names: a display-only assertion or a process in CoreAudio's playing list is media; a process's own system assertion is work, which turns the final action into `pmset displaysleepnow`. Apps (`.app/`) are never daemons, Apple's under `/System/Applications` included. Re-measure with `IOPMCopyAssertionsByProcess` before changing a rule.
- `CameraWatcher` runs the session while any user (the night watch's look, the Settings preview) holds it, and never prompts for access. Verify the camera went off from the log (`category == "camera"`: "Camera on for …", "Camera off"); drive the UI through `capture-screenshots.sh`'s flow, because a hand-sent status-item click toggles the panel and lands half the time on a closed one.
- `PresenceCheck` measures seconds from frame timestamps, never frame counts: the built-in camera delivered ~14 fps where 10 were asked (measured 2026-10-05), and auto exposure can slow it in the dark. `EyeReading` calls eyes closed only when Vision's EAR (below 0.20) and Core Image's blink classifier agree: EAR alone took 17 of 46 open-eyed photos for closed. Change either rule only against `EyeDetectionBenchmark` (skipped without `WMS_FACE_DIR`; method, results and caveats in `docs/eye-detection.md`). To watch a look live, log from inside `WatchMeSleepCore` (the executable target cannot see internal API) and launch the signed bundle with `open --env`, so TCC asks about the app, not the terminal.

## UI

Supports the three latest macOS releases (currently 14+) on Apple silicon only, and follows Apple's HIG; `#available(macOS 26.0, *)` branches are the Liquid Glass path, the else branches serve 14 and 15.

Menu-bar `.accessory` app: `SettingsView` lives in a custom `NSWindow` opened by `AppDelegate`, and the dropdown is a custom borderless `NSPanel` (`MenuBarPanel.swift`), not an `NSPopover`. The three load-bearing panel rules (`sizeThatFits` height, material backing kept at the AppKit level, pinned `.frame(width:)` plus layer-backed corner rounding): `docs/ui-architecture.md`.
